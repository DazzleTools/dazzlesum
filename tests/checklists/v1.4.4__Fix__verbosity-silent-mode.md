# Human Test Checklist: Verbosity & Silent-Mode Fixes

**Target version:** 1.4.4
**Ships with commit:** TBD (v1.4.4)
**Companion automated tests:** 12 in `tests/test_verbosity_system.py` (all green; first fully green suite since v1.3.6), 125 total

## What this is

v1.4.4 makes silent mode real: `-qqqqqq` / `--verbosity=-6` was unreachable (clamped to -5) and returned exit code 0 regardless of failures because the aggregate exit code was computed as a side effect of *displaying* grand totals. Level defaults also changed: extras-only directories now appear at -1 (as documented) and hide at -2; -3/-2 keep -4's forced status lines so raising verbosity never removes information. These are automation contracts (CI scripts branch on silent mode's exit codes) and terminal-rendering behaviors — the exact category mocks can't fully cover.

## Prerequisites

Repo root, any shell. Build a throwaway fixture with one good file, one corrupted manifest entry, and one extras-only dir:

**PowerShell**:
```powershell
$env:VBOX = "$env:TEMP\dz-verbosity-check"
if (Test-Path $env:VBOX) { Remove-Item -Recurse -Force $env:VBOX }
New-Item -ItemType Directory -Force "$env:VBOX\good","$env:VBOX\bad","$env:VBOX\extras" | Out-Null
Set-Content "$env:VBOX\good\ok.txt" "ok"
python dazzlesum.py create -r "$env:VBOX"
Set-Content "$env:VBOX\bad\tampered.txt" "changed"
python dazzlesum.py create "$env:VBOX\bad"
Set-Content "$env:VBOX\bad\tampered.txt" "changed again"
Set-Content "$env:VBOX\extras\stray.txt" "extra"
```

**POSIX**: same shape with `export VBOX=/tmp/dz-verbosity-check`, `mkdir -p`, `echo`.

Reset: delete `$env:VBOX` and rebuild.

## High-Value Verification (~3 minutes)

### HV.1 — Silent mode is actually silent

- [ ] **Steps** (PowerShell): `python dazzlesum.py verify -r -qqqqqq "$env:VBOX"; "exit=$LASTEXITCODE"`
  (cmd: `... & echo exit=%ERRORLEVEL%`; POSIX: `...; echo exit=$?`)
- [ ] **Expected:** ZERO lines of output (no banner, no totals) — only your `exit=N` echo, with **N != 0** (the fixture has a failure).
- [ ] **Why:** Before 1.4.4, "silent" printed the banner + grand totals AND exited 0 on failures — a broken automation contract on both ends.

### HV.2 — Silent exit codes track reality

- [ ] **Steps:** run HV.1 against ONLY the good dir: `python dazzlesum.py verify -r -qqqqqq "$env:VBOX\good"`
- [ ] **Expected:** exit 0. (Failing tree from HV.1: nonzero, typically 5.)

### HV.3 — Ladder never shrinks

- [ ] **Steps:** run `verify -r` on the fixture at `-qqqq`, `-qqq`, `-qq`, `-q` and count per-directory status lines (lines with a path + "verified,").
- [ ] **Expected:** counts non-decreasing as verbosity rises; the extras-only dir appears at `-q` (-1) but NOT at `-qq` (-2).
- [ ] **Why:** -4→-3 and -2→-1 previously LOST lines as verbosity increased.

### HV.4 — EXTRA_SUMMARY still works as explicit opt-in

- [ ] **Steps:** `python dazzlesum.py verify -r --squelch EXTRA_SUMMARY "$env:VBOX"`
- [ ] **Expected:** extras-only dir's status line hidden; failing dir still shown. (The category moved out of -1's defaults but remains user-selectable.)

### HV.5 — Real cmd.exe rendering (human-only)

- [ ] Run HV.1 and HV.3 in a plain cmd.exe window: clean ASCII, no stray color codes at -6 (truly nothing), sane wrapping at 80 cols.

## What the automated tests DON'T cover

- Real terminal rendering (codepage, color codes, width) at each level
- `%ERRORLEVEL%` / `$?` behavior in real shells (subprocess tests approximate it)
- The *feel* of the level ladder — whether each step's added detail is what a user expects
