## Checks (~10 minutes)

### 1 -- The flag is rejected, loudly and with the right exit code

- [ ] **Steps**:

  **cmd.exe**:
  ```cmd
  dazzlesum create --force-python %TEMP%
  echo exit=%ERRORLEVEL%
  ```

  **PowerShell**:
  ```powershell
  dazzlesum create --force-python $env:TEMP
  "exit=$LASTEXITCODE"
  ```

  **POSIX**:
  ```bash
  dazzlesum create --force-python /tmp; echo "exit=$?"
  ```
- [ ] **Expected:** argparse usage error naming `--force-python` as unrecognized; exit code 2. NOT a silent success, NOT a traceback.
- [ ] **Why this matters:** scripts that passed the (previously inert) flag must fail visibly at the parser, not deep in a run.

### 2 -- The stitched artifact rejects it identically

- [ ] **Steps** (from the repo root, by path): `python dazzlesum.py create --force-python .` then check the exit code as above.
- [ ] **Expected:** same usage error, same exit 2. Package and artifact must not diverge on CLI surface.

### 3 -- No misleading engine banner remains

- [ ] **Steps** (PowerShell; note logs are on stderr):
  ```powershell
  dazzlesum create $env:TEMP\dazzlesum-chk -vvvv 2>&1 | Select-String -Pattern "Forcing|implementation"
  ```
  (Create the folder with a file in it first.)
- [ ] **Expected:** `Using Python implementation for sha256` appears; the old "Forcing Python implementation" line appears NOWHERE under any flag combination.

### 4 -- Directory argument works as the new examples show

- [ ] **Steps**: from your home directory (not the target, not the repo):
  ```
  dazzlesum create -r <some scratch folder with files>
  dazzlesum verify -r <same folder>
  ```
- [ ] **Expected:** manifests written into the TARGET folder, not the cwd; verify passes with exit 0. Try one quoted path with spaces.

### 5 -- The docs stand where they claim to

- [ ] **Steps**: on GitHub (or locally), follow the README's platform badge and its Platform Support section link; skim `docs/platforms.md`.
- [ ] **Expected:** badge resolves to `docs/platforms.md` (not an in-page anchor); the doc's internal links (command-reference exit codes, unctools) resolve; no `--force-python` reference survives anywhere in README or docs except as "removed in 1.5.1" migration notes.
