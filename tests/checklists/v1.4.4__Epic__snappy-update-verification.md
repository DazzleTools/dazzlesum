# Human Test Checklist: "Feels Like Everything" Update Verification

**Target version:** 1.5.0 line (forward-looking -- written BEFORE the detection-source code; this is the acceptance bar that work must clear)
**Companion automated tests:** `tests/test_update_mode.py` (grows with each layer)

## What this is

The 1.5 goal: updating checksums for an entire multi-million-file collection should feel like Everything (voidtools) -- silent, near-instant, and identical in behavior on Windows, Linux, macOS, and BSD. Three detection layers feed one update engine, cheapest-first: **git-record hints** (changed metadata marks dirty neighborhoods), **file/folder mtime sweep** (the universal baseline), and the **NTFS USN journal** (Windows passive accelerator). This checklist defines how a human verifies each layer and the end-to-end feel, so every increment of that work is judged against the same bar.

Any new detection-layer code MUST be run against this checklist before its release, with the execution record appended.

## The bar (quick reference)

| Scenario | Target |
|---|---|
| Steady-state full sweep, 2.5M files (nothing changed) | Minutes, single digits preferred; zero rehashes; zero manifest rewrites |
| Touch 1 file anywhere, hint-driven update | Seconds |
| Touch 1 file anywhere, full sweep finds it | Same sweep time; exactly 1 rehash |
| Bootstrap a fresh machine (manifests present, no cache) | Under an hour with `--bootstrap trust` |
| Any of the above on Linux/mac/BSD | Same semantics, no Windows-only dependency in the core |

## Basic self-check list (the 5-minute version)

Run these yourself whenever update-speed code changes; each is one command plus a glance:

- [ ] **1. The nothing-changed sweep.** `dazzlesum update -r --shadow-dir <shadow> <root>` on your library. Watch the clock and the final line: `0 rehashed, 0 manifests rewritten`, wall time in single-digit minutes.
- [ ] **2. The needle test.** Edit ONE file deep in the collection. Re-run the sweep. Final line shows exactly `1 rehashed, 1 manifests rewritten`, same wall time.
- [ ] **3. The backdate test** (sync safety). Change a file's content AND set its mtime into the past (`python -c "import os; os.utime(p, ns=(old,old))"`). The sweep must still catch it.
- [ ] **4. The hint test.** `echo <that-folder> | dazzlesum update -r --dirs-from - --shadow-dir <shadow> <root>` -- finishes in seconds, touches only that folder.
- [ ] **5. The silence test.** Add `-qqqqqq`: zero output, and `%ERRORLEVEL%` / `$?` still meaningful.
- [ ] **6. The cache-loss test.** Delete `.dazzle-cache.sqlite`; `--bootstrap trust` rebuilds it without rehashing; the NEXT sweep is back to test-1 speed.

If all six hold, the update path is healthy. Anything slower or noisier than the bar is a regression even if tests pass.

## Section 1: mtime-sweep layer (the universal baseline)

### 1.1 Cold vs warm sweep timing
- [ ] Time a bootstrap (empty cache) and the immediately following sweep on the same tree. Record both. Warm must be dramatically faster (fast path: scandir + one SELECT per folder).

### 1.2 Every change type detected in one sweep
- [ ] In one pass, prepare: a modified file, an added file, a deleted file, a same-size backdated-mtime modification, a touched-but-identical file. Run one sweep. Expected: 2-3 rehashes reported honestly (`modified`, `added`, `touched` rehashes; `deleted` removed; backdated caught), and only genuinely changed manifests rewritten.

### 1.3 Cross-platform parity (per platform: Linux, macOS, BSD)
- [ ] Repeat the basic self-check list items 1-3 and 6. Same semantics, no degraded mode. Note filesystem-specific mtime granularity behavior (ext4 ns, APFS ns, UFS).

## Section 2: git-hint layer (when built)

- [ ] Commit a metadata change (README, .shasum) in the library repo; the hint hook/script emits the containing folder (+N neighborhood levels) to a dirs list; `--dirs-from` consumes it; only those folders are examined.
- [ ] Verify the hint layer NEVER claims completeness: docs and output must state it's advisory (binary content changes are invisible to git); the periodic full sweep remains the backstop.
- [ ] Hint + no actual change = zero rehashes, zero rewrites (hint nominates, engine verifies).

## Section 3: USN-journal layer (when built, Windows only)

- [ ] With the watcher/checkpoint running, modify a file WITHOUT any dazzlesum invocation; the next hint-driven update (fed from USN) catches exactly that file's folder in seconds.
- [ ] Journal wrap / checkpoint loss degrades gracefully to "full sweep needed" -- loudly, not silently.
- [ ] USN layer absent (any non-Windows box): everything still works via Sections 1-2.

## Section 4: The "feel" (human judgment, every release of this line)

- [ ] Does the steady-state sweep feel like a status check rather than a job you schedule?
- [ ] Is the default output calm -- progress lines you'd tolerate watching, a final line you can read in one glance?
- [ ] Could you explain to another person, in one sentence each, when to use: plain `update`, `--dirs-from`, `--paranoid`, `verify`?

## What the automated tests DON'T cover

- Wall-clock feel at real scale (fixtures are small; the library is the benchmark)
- Filesystem-specific mtime semantics across platforms
- USN journal behavior (hardware/OS state, wrap conditions)
- The subjective "Everything-like" bar in Section 4

## Execution record

_Append one dated row-set per verification run, per release of the 1.5 line._

**Baseline (v1.4.3/v1.4.4 code, 2026-07-17):** full trust-bootstrap of the D:\M library (**182,491 dirs / 3,367,354 files** -- larger than any prior estimate): **40.73 min**, vs the v1-schema run's ~7.5h projection (11x). Report: 3 rehashed, 3 added, 1,022 removed (real drift since the original scan), 551 manifests rewritten, 220 failed (ACL-locked files, entries preserved), exit 2 (completed-with-failures semantics correct). Steady-state (warm cache, fast path) sweep: **32.83 min** (182,491 dirs / 3,367,357 files; 0 rehashed, 0 rewritten, 220 perennial ACL failures). **Misses the single-digit-minutes bar** -- at ~10.8 ms/dir the cost is enumeration-side (per-file Path construction + exclude matching, per-dir junction lstat, interpreter loop overhead), NOT hashing or cache writes. This is the target number for the 1.5 speed work; threaded scandir (GIL-releasing) is the first lever to evaluate. Also noted: permanently unreadable files (ACL-locked) fail every sweep, so exit code is 2 forever -- consider a skip/ignore mechanism so steady-state can reach exit 0.
